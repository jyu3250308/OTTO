# 캐럿블링크 🥕⚡ — 중고 꿀매물 '실질 마진' 감지봇

> 🆕 **v3 FINAL (2026-07-30)** — 이 봇은 **실제로 3일간 무인 운영된 결과물**입니다.
> 스캔 14회차, 매물 수천 건을 돌리면서 나온 실패를 하나씩 막아 만든 최종 버전이에요.
> v1·v2가 왜 틀렸는지가 곧 이 봇의 기능입니다.

## 이 봇이 하는 일

당근마켓에서 **시세보다 싸게 나온 매물**을 찾아주는 봇은 많습니다.
이 봇이 다른 점은 **"그거 사서 어디에 팔면 얼마 남는지"까지 계산한다**는 점입니다.

```
번개장터 매도 시세 × (1 - 판매수수료) - 택배비 - 당근 매수가 = 손에 남는 돈
                                                              ↑ 이 값으로 판정
```

3만원도 안 남으면 알리지 않습니다. 움직일 가치가 없으니까요.

## 왜 이렇게 만들었나 — 3일간의 실패 기록

이 부분이 이 봇의 핵심입니다. 코드만 보면 왜 이렇게 복잡한지 이해가 안 되실 거예요.

### v1의 실패: "같은 이름이면 같은 물건인 줄 알았다"

첫 버전은 단순했습니다. *"같은 키워드 매물 20건의 중앙값 = 시세, 그 70% 이하면 꿀매물."*
1일차에 후보 27건이 잡혔습니다. 그런데 열어보니 **대부분 꿀매물이 아니라 구형 세대**였어요.

- "에어팟 프로" 시세 8만원(1·2세대 혼합) → 1세대 2.5만원 매물이 *"70% 미만! 꿀매물!"*로 잡힘
- 사실 그건 **1세대 제값**이었습니다

→ **대책**: 제목에서 모델 토큰을 읽어(1세대/2세대, 에어5, OLED, 세트번호…) **같은 모델끼리만** 비교

### v2의 실패: "게임을 게임기로 착각했다"

모델별로 비교하게 바꾸고 돌렸더니, **닌텐도 스위치 시세가 4만원**으로 나왔습니다.
스위치 본체가 4만원일 리가 없죠. 매물 97건을 직접 열어봤습니다.

- **절반 이상이 '게임 타이틀'**이었습니다 ("포켓몬스터 소드 3.5만원", "젤다 야숨 4.5만원"…)
- 검색어 '닌텐도 스위치'는 **게임기와 게임을 같은 이름으로 부릅니다**
- 그 결과 게임 가격이 시세를 끌어내려 **진짜 본체(15~25만원)가 전부 '꿀매물'로 오탐**

제외어로는 막을 수 없었습니다. 게임 이름은 무한히 많으니까요.

→ **대책**: 품목별 **'본품 최소가' 상식**을 주입 (스위치 9만 / 아이패드 10만 / 에어팟프로 3만).
"이 물건이 이 값일 리 없다"는 판단은 데이터가 아니라 상식의 영역이었습니다.

### v3에서 또 나온 실패: "파는 쪽이 설계에 없었다"

여기까지 하고 나서 결정적인 질문을 받았습니다. **"그래서 사서 어디다 팔아?"**
마진을 당근 안에서만 계산하고 있었던 겁니다. 번개장터 시세를 붙여봤더니:

```
당근  아이패드 미니6 중앙값: 420,000원
번개  아이패드 미니6 중앙값: 420,000원   ← 똑같음
```

**플랫폼 간 시세 차이는 존재하지 않았습니다.** "싼 데서 사서 비싼 데 판다"는 그림은 없었어요.
돈이 되는 건 오직 *그 시장 안에서 유독 싸게 나온 개별 매물* — 즉 **시장의 실수**뿐입니다.

그리고 번개 시세를 붙이자마자 또 틀린 값이 나왔습니다:

```
아이패드 프로11: 당근 53.7만 → 번개 108만 = "실질 마진 75만원"(?!)
```

프로11 그룹 안에 **2018년형부터 M5까지** 섞여 있었고, 당근엔 구형이·번개엔 최신형이 많이
올라와서 마진이 허구로 부풀었던 겁니다. **세 번째로 같은 실수를 한 셈이었습니다.**

→ **대책**: 아이패드 프로는 인치+세대까지 분리(칩 이름 'M1'과 '3세대'를 같은 칸으로 정규화)
+ **매도가가 매수가의 1.6배를 넘으면 "두 시장이 서로 다른 물건을 보고 있다"고 판단해 판정 포기**

## 핵심 원칙: 모르면 알리지 않는다

이 봇은 **'판정 보류'를 아주 많이 냅니다.** 일부러 그렇게 만들었습니다.

| 상황 | 처리 |
|---|---|
| 제목만으로 모델을 특정할 수 없음 (예: 기계식 키보드의 축·브랜드) | 판정 보류 |
| 같은 모델 표본이 6건 미만 | 판정 보류 |
| 팔 곳(번개) 시세를 모름 | 판정 보류 |
| 매도가/매수가 비율이 비정상 | 판정 보류 |
| 하자·부분품 표현 감지 (고장·침수·한쪽·액정 깨짐…) | 제외 |
| 같은 모델 중 **혼자만 유독 쌈** | 후보로 올리되 **⚠️ 가품·하자 의심 경고** |

마지막 항목이 실전에서 특히 유용했습니다. 에어팟 프로2 그룹에서 54,000원 매물이 하나
잡혔는데, 두 번째로 싼 게 85,000원이었어요. 3만원이나 혼자 아래였습니다.
**싼 게 아니라 싼 이유가 있을 가능성**이 크죠(에어팟은 가품 비율이 특히 높은 품목입니다).

많이 찾아주는 봇보다 **헛걸음을 안 시키는 봇**이 실제로 쓸모 있다고 판단했습니다.

## 보너스: '호가'가 아니라 '실제 팔리는 가격' 알아내기

우리가 시세라고 부르는 건 사실 **올라온 매물의 호가**입니다. 안 팔린 매물은 계속 남아 있으니
호가 중앙값은 실제 체결가보다 **높게 편향**됩니다.

그래서 이 봇은 실행할 때마다 **매물의 생존 여부를 추적**합니다.
목록에서 사라진 매물 = 팔렸을 가능성이 높은 매물 → 그 가격대가 **실제 거래되는 가격**에 가깝습니다.

```
📉 판매추정 매물 12건의 가격 중앙값: 118,000원
   (호가 중앙값이 143,000원이라면 → 실제로는 더 싸게 팔린다는 뜻)
```

**반복 실행할수록 정확해지는 구조**입니다. 이게 이 봇을 스케줄러에 걸어둘 이유입니다.

## 실행 방법

**필요한 것: 없습니다.** 표준 라이브러리만 사용하고, API 키도 계정도 필요 없습니다.

```bash
python carrot_blink_bot.py                  # 기본 5개 품목 스캔
python carrot_blink_bot.py "아이패드"         # 원하는 품목만 스캔
```

끝입니다. Python 3.7 이상이면 됩니다.

### 결과물

- **콘솔 요약** — 모델별 시세, 실질 마진 후보, 판정 보류 건수
- **`reports/carrot_v3_날짜.html`** — 썸네일·계산 내역·경고가 담긴 리포트 (브라우저로 열어보세요)
- **`history.json`** — 매물 생존 추적 누적 (실행할수록 쌓입니다)

### (선택) 텔레그램 알림

환경변수 두 개만 넣으면 후보를 텔레그램으로 받습니다. 없으면 조용히 생략되니 신경 안 쓰셔도 됩니다.

```bash
set TELEGRAM_BOT_TOKEN=your_token       # Windows
set TELEGRAM_CHAT_ID=your_chat_id
```

### 무인 감시로 돌리기

윈도우 작업 스케줄러나 cron에 **3시간 간격**으로 등록하세요.
새 매물 감지 + 체결가 데이터가 동시에 쌓입니다.

```bash
# cron 예시 (매일 8시부터 3시간마다)
0 8,11,14,17,20 * * * cd /path/to/bot && python carrot_blink_bot.py
```

## 내 조건에 맞게 조정하기

파일 상단 상수만 바꾸면 됩니다.

```python
KEYWORDS = ["아이패드", "닌텐도 스위치", ...]   # 감시할 품목
MIN_NET_MARGIN_KRW = 30000                    # 이만큼 안 남으면 안 알림
BUNJANG_FEE_RATE = 0.035                      # 판매 수수료 (추정치 — 본인 조건으로)
SHIPPING_COST_KRW = 4000                      # 택배비
MIN_ITEM_PRICE = {"아이패드": 100000, ...}      # 품목별 '본품 최소가' 상식
```

새 품목을 추가할 때는 `MIN_ITEM_PRICE`에 하한을 꼭 같이 넣어주세요.
**그게 없으면 v2의 실패(게임을 게임기로 착각)가 그대로 재현됩니다.**

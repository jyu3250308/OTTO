## 💡 프로젝트 개요

`Debug_Diviner`는 AI의 눈으로 GitHub 저장소의 이슈들을 깊이 분석하여, 개발자들이 흔히 겪는 버그들의 **핵심 반복 패턴**을 식별합니다. 복잡한 수많은 이슈 속에서 특정 버그의 근본 원인과 해결책에 대한 통찰을 단 세 줄의 '예언서'로 압축하여 제공합니다. 이 독점적인 패턴 분석 결과는 개발자들이 버그 디버깅에 소모하는 막대한 시간과 비용을 획기적으로 절약해 줄 것입니다. 

**버그 투성이 코드 속에서 황금을 캐내는 AI 채굴자!** 💰

## 🌟 주요 기능

*   **이슈 데이터 모킹**: 실제 GitHub API 연동을 모방하여 버그 이슈 데이터를 가져옵니다. (현재는 Mock 데이터 사용)
*   **AI 기반 패턴 분석**: 모킹된 LLM(대규모 언어 모델)을 사용하여 이슈 텍스트에서 버그 패턴을 추출합니다.
*   **3줄 디버깅 예언서 생성**: 발견된 버그 패턴을 '예언', '해결책', '패턴'의 3가지 핵심 문장으로 요약하여 제공합니다.
*   **콘솔 출력**: 분석 과정을 친절하게 콘솔에 표시하여 진행 상황을 쉽게 이해할 수 있습니다.

## 📜 코드 설명 (debug_diviner.py)

`debug_diviner.py` 파일은 다음과 같은 주요 부분으로 구성되어 있습니다:

*   `MOCK_GITHUB_ISSUES_DATA`: 실제 GitHub 이슈 데이터를 시뮬레이션하는 리스트입니다.
*   `mock_llm_predict(issue_text)`: 실제 LLM의 예측을 모방하여 3줄 예언서를 생성하는 함수입니다. 입력 이슈 텍스트에 따라 다른 예언을 반환합니다.
*   `fetch_github_issues_mock(repo_owner, repo_name)`: Mock 데이터를 사용하여 특정 저장소의 열려있는 버그 이슈들을 가져오는 함수입니다.
*   `analyze_issues(issues)`: 가져온 이슈들을 `mock_llm_predict` 함수를 통해 분석하고 개별 예언서(blueprint)를 생성합니다.
*   `generate_final_blueprint(all_blueprints)`: 모든 개별 예언서들을 통합하여 최종 '디버깅 예언서'를 생성합니다.
*   `main()`: 프로그램의 진입점 역할을 하며, 위의 함수들을 호출하여 전체 과정을 실행합니다.

## ⚠️ 주의사항 및 면책 조항

*   **Mock 버전**: 현재 `Debug_Diviner`는 **모의(Mock) 버전**입니다. 실제 GitHub API와 연동되지 않으며, 내부적으로 정의된 `MOCK_GITHUB_ISSUES_DATA`와 `mock_llm_predict` 함수를 사용하여 동작합니다. 따라서 실제 최신 GitHub 이슈를 분석하는 것이 아닌, 미리 정의된 가상 시나리오를 실행합니다.
*   **API 한도**: 이 Mock 버전에서는 해당되지 않지만, 만약 실제 GitHub API와 연동하는 시스템으로 확장될 경우, GitHub API의 요청 제한(Rate Limit)에 주의해야 합니다. 과도한 요청은 일시적인 접근 차단을 유발할 수 있습니다.
*   **데이터 손실 위험 없음**: 이 스크립트는 단순히 Mock 데이터를 읽고 처리하며, 어떠한 파일도 쓰거나 외부 시스템의 데이터를 변경하지 않습니다. 따라서 실행 중 데이터 손실 위험은 전혀 없습니다.
*   **예언의 정확성**: `mock_llm_predict`는 단순한 키워드 매칭 기반의 모의 예측입니다. 실제 LLM은 훨씬 복잡하고 정확한 패턴을 찾아내지만, 이 버전은 개념 증명(PoC) 목적이므로 실제와 같은 고품질의 예언을 기대하기는 어렵습니다.
